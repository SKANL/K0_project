# Security Policy

## Report a vulnerability privately

Please **do not** open a public issue, discussion, or pull request for a suspected vulnerability, exposed credential, security-control bypass, or exploit detail.

Use [GitHub's private vulnerability reporting](https://docs.github.com/code-security/security-advisories/working-with-repository-security-advisories/about-repository-security-advisories) for this repository. If private reporting is unavailable, contact the repository maintainers through GitHub and share only a minimal, redacted summary until a private channel is established.

## Include

- Affected version, commit, or release asset.
- A minimal reproduction and expected versus actual behavior.
- Impact, affected surface, and any mitigations already applied.
- Logs, screenshots, or artifacts only after removing credentials, personal data, signing material, and private URLs.

## What happens next

Maintainers will acknowledge a valid report, assess impact, coordinate a fix privately, and publish disclosure information when users can act safely. Please allow time for triage and remediation before public disclosure.

## Scope

This policy covers the repository, published release assets, updater metadata, CI/release workflows, and dependencies used by K0. Configuration and deployment choices outside this repository remain the operator's responsibility.

For non-security support, see [SUPPORT.md](./SUPPORT.md).
